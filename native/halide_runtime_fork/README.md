# Halide Vulkan runtime fork — VkPipelineCache persistence (R3-3, 2026-07-05)

## What this is

A minimal fork of the Halide **v21.0.0** Vulkan runtime module that adds
cross-launch `VkPipelineCache` persistence (upstream calls
`vkCreateComputePipelines` with `VK_NULL_HANDLE`, so every process launch pays
full pipeline compilation — ~780 ms of the Android startup warmup on SM8650).

## Provenance & layout

| Path | Status |
|---|---|
| `upstream/**` | **Pristine** Halide v21.0.0 `src/runtime` sources (include closure of `vulkan.cpp`, fetched from `https://github.com/halide/Halide/tree/v21.0.0/src/runtime` — see `third_party/halide/VERSION` for the vendor pin). Never edit. |
| `vulkan.cpp` | Patched copy of `upstream/vulkan.cpp`. `diff upstream/vulkan.cpp vulkan.cpp` = whole delta. |
| `vulkan_resources.h` | Patched copy of `upstream/vulkan_resources.h`. |
| `dng_vk_pipeline_cache_persist.h` | **New file** — all persistence logic. |

All changes are tagged `[DNG-FORK R3-3]`. Quoted includes resolve to this
directory first (patched files), then fall back to `-I upstream/`.

## How the override works (link-level)

`halide_runtime.a` (generated by `dng_demosaic_generator -r`) is a single
object whose `halide_vulkan_*` entry points are **weak** symbols and whose
module globals (`compilation_cache`, `cached_device`, vk function-pointer
table, `vulkan_allocation_pool`) are **weak external** — verified with
`llvm-nm` (the one-off verification script `r3_3_nm_runtime_symbols.sh` used
during R3-3 was deleted in the R3-5 scripts/tmp/ cleanup; re-run an
equivalent `llvm-nm -D --defined-only` check on `halide_runtime.a` if this
needs re-verifying). The upstream re-fetch entry for this fork's source
material lives at `scripts/fetch_halide_v21_runtime.sh` (promoted to tracked
in R4 C2-1; was `scripts/tmp/fetch_halide_v21_runtime.sh`). Compiling this TU
into the target makes its definitions win (objects precede archives on the
link line), while state stays single-copy. Internal anonymous-namespace
helpers in the archive become dead code. One trap is documented in
`vulkan.cpp`: the upstream `__attribute__((constructor))` pool registration
must be omitted here (the archive's copy still runs; two registrations would
self-cycle the pool list).

## Switches

- **Compile time**: CMake option `DNG_VK_PIPELINE_CACHE` (Android-only,
  default ON). OFF ⇒ this directory is not compiled; stock runtime behavior.
- **Runtime**: inert unless a cache path is set via FFI
  `dng_decoder_set_pipeline_cache_path()` / `dng_vk_pipeline_cache_set_path()`
  or env `DNG_VK_PIPELINE_CACHE_PATH`. Env `DNG_VK_PIPELINE_CACHE=0`
  force-disables. Verbose evidence lines (`[VkPCache] ...`) require
  `DNG_PIPELINE_VERBOSE=1`.
- **Prewarm skip (R3-3 Option B, user-approved)**: on a validated cross-launch
  cache HIT (status bit 4), `dng_pipeline_warmup_for_size` skips the
  full-size S3/S4 prewarm dispatches (via `dng_vk_pipeline_cache_prepare()`).
  `DNG_VK_SKIP_PREWARM_ON_HIT=0` restores the full prewarm while keeping the
  cache active; control / corrupted / driver-mismatched cache all run the
  full prewarm automatically (bit 4 unset).

## Invalidation & corruption safety

Cache file = envelope header (magic `DNGVKPC1`, version,
vendorID/deviceID/driverVersion/pipelineCacheUUID, payload size, FNV-1a 64
hash) + `vkGetPipelineCacheData` payload. Any mismatch/truncation ⇒ silent
empty-cache fallback. Writes are atomic (`<path>.tmp` + `rename`). Cache
failure can never fail a decode: pipeline creation retries with
`VK_NULL_HANDLE` on any cache-path error.

## Maintenance debt (known limitation, accepted in R3 planning)

This fork pins to Halide v21.0.0. A Halide version bump requires re-fetching
`upstream/` and re-applying the `[DNG-FORK R3-3]` delta (3 tagged edit sites +
1 new header).
