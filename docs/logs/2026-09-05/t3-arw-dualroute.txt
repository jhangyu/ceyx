WHY THIS MATTERS TO THE CAMPAIGN (for lead/user triage, not fixed here):
 * AC5 requires byte-identical colour under 5-way concurrency. A route
   that intermittently FAILS to decode under that same load is a prior
   problem sitting on the campaign's critical path.
 * Any ARW gate run has a ~15-20% chance of a spurious red per run, so a
   single red ARW gate must not be read as a regression without a repeat.
 * -206 is kRawErrMetadataInvalid, the same code the quarantined
   image_samples/raw_sample.arw returns, which suggests shared/racing
   metadata state rather than pixel corruption.

HOW IT WAS FOUND (instrument note): the first run of this artifact used
'<binary> ... | tail -4; RC=$?', which captures tail's exit code, not the
binary's. That printed RC=0 failures=0 and hid the failure. Re-running
with the exit code captured directly off the binary exposed it on the
first attempt. Same defect family as the campaign's own instrument rule.
