## 🔍 Debug 發現與反思 (修改 Code 前記錄)

### 當前遇到的問題
在導入 Phase 5.3 的 ProfileToneCurve 之後，測試結果發現：
1. 26 個測試通過，但 Test 6.5 PSNR 測試失敗。
2. PSNR 從原本的 `19.34 dB` 驟降至 `12.39 dB`。
3. 輸出的影像平均 RGB 值為 `(39.9, 36.3, 41.0)`（255尺度），顯示影像嚴重變暗（shadows crushed）。

### 推導過程與源碼解讀
為了找出 PSNR 下降的原因，我查閱了 Adobe DNG SDK 原始碼 (`dng_render.cpp`)，發現了兩個致命的實作錯誤：

**1. Tone Curve 套用順序錯誤**
我們原先計畫的順序是：`HueSatMap -> ToneCurve -> LookTable`。
但 DNG SDK `dng_render_task::ProcessArea` 中的實際執行順序是：
- `DoBaselineHueSatMap` (HueSatMap)
- `DoBaseline1DTable` (ExposureRamp)
- `DoBaselineHueSatMap` (LookTable)
- `DoBaselineRGBTone` (ToneCurve)
也就是說，**Tone Curve 必須在 LookTable 之後套用**。

**2. ACR 預設曲線 (ACR3 Default) 參數錯誤與域值錯誤**
我們原本使用了 14 個控制點 `(0.000, 0.000), (0.053, 0.000)...` 進行分段線性插值。這個曲線直接將小於 `0.053` 的線性亮度映射到了 `0`，這導致了暗部細節全部丟失。
查閱 SDK 後發現，`dng_tone_curve_acr3_default::Evaluate` 實際上是使用一個 **513 個元素 (513-entry)** 的 Look-Up Table (LUT) 陣列，而不是簡單的 14 點 spline。它在 `index 1` 也就是 `x=1/512` 時的輸出是 `0.00078f`，這保留了平滑的暗部過渡。

### 預計的解決思路 (Next Steps)
1. **替換曲線實作**：將 HalidePipeline.cpp 中的 14 點 `kAcrDefaultCurve` 移除，替換為這 513 個元素的 `kAcrDefaultLUT` 矩陣，並搭配 `evalAcrLUT` 來用線性插值讀取。
2. **調整套用順序**：將 Tone Curve 程式區塊 (Step 5d) 從 HueSatMap 與 LookTable 之間，**往下移動到 LookTable 之後**。
