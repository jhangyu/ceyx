# 程式碼索引更新規範 (Update Code Index Rule)

這份文件定義了在大型程式碼檔案（單一檔案大於約 100 行）開頭建立與維護 YAML 索引的詳細規則，供模型在讀寫程式碼時嚴格遵守。

## 1. 索引目的
- 讓模型在修復或擴充程式碼前，只需讀取檔案的最前 100 行即可掌握整個檔案的架構與每個 function 的確切位置。
- 避免載入過大的檔案內容，節省 Context Token 並提升模型的理解與修改準確度。

## 2. 索引內容要求
索引必須由 `file_summary` 和 `functions`（或 `modules`）組成：
- **file_summary**: 一句話簡述該檔案的整體責任與用途。
- **functions**: 詳細列出檔案中的每一個主要 function、class 或是邏輯區塊，並包含以下三個欄位：
  - `name`: 函式、類別或模組的名稱。
  - `description`: 該區塊的具體功能描述，包含主要邏輯說明。
  - `lines`: 該函式的確切起始與結束行號（例如 "120-150"）。

## 3. 範例格式
請使用區塊註解（例如 C/C++ 的 `/* ... */`，Dart 的 `//` 或 `/* ... */`，Python 的 `""" ... """`）將索引包裹在檔案最開頭的部分：

```yaml
/*
---
file_summary: "負責影像解碼與後處理的核心處理層"
functions:
  - name: "rgb2hsv"
    description: "將 RGB 色彩空間轉換為 HSV"
    lines: "64-88"
  - name: "HalidePipeline::process"
    description: "管線主入口：將原始數據送入 Halide Graph 並量測執行時間"
    lines: "1000-1150"
---
*/
```

## 4. 更新時機與維護責任
- **新增/刪除區塊**：當新增了 function 或模組時，必須同步在檔案開頭的索引區塊加入新的項目。
- **行數變動**：當由於修改代碼，導致某個 function 的起始或結束行數發生顯著偏差時，應更新索引中的 `lines` 範圍，以保持索引的準確性。
- **重構**：若模組職責改變，也須同步更新 `description`。
- **強制回查**：模型於完成特定代碼修改後，應回頭檢查該檔案的第一個區塊，更新對應的行數或增減的 Function。
